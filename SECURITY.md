# Security policy and threat model

Again sits on the path of agent-generated shell commands. A bug can change command semantics, leak output, or weaken an approval boundary, so conservative misses are a feature.

## Non-negotiable rules

- Unknown means do not cache; never infer purity from popularity or repeated equality. An ineligible explicit `again run` call errors without executing the command. The caller must rerun the original argv unchanged outside Again; Again never runs it on the caller's behalf.
- Production automatic Codex hook rewriting is disabled: the hook returns before reading or parsing stdin and emits no allow decision. Codex hides effective TTY, workdir, shell/login, sandbox and remote-environment controls, so a transparent wrapper cannot preserve the complete invocation semantics.
- The active MVP is explicit local/default-environment `again run -- <argv...>`, which resolves and validates the executable from the tool shell's actual context. If any standard stream is a TTY, the audited command executes once uncached with inherited streams.
- Dormant hook plumbing accepts only the exact audited envelope, requires `tool_input` to contain only `command`, and requires an explicit absolute audited executable before it can create an opaque handoff. Original shell text is never interpolated into that handoff. If explicitly enabled with the conspicuously unsafe test flag, a hidden TTY or same-repository cwd difference executes the revalidated command once uncached with inherited streams; a different repository/non-Git cwd or remote executable/state mismatch can fail. The flag is for controlled differential tests only and must not be installed as a production hook.
- The v0 command surface accepts only `pwd -P`, requires `ls --color=never`, requires every `grep` and `rg` to have at least one explicit path operand, and additionally requires every `rg` to use `--no-ignore --sort=path`. `RIPGREP_CONFIG_PATH` disables admission, and explicit recursive `.git` directories or aliases to them are rejected.
- Active policy `strict-read-v0.5` admits exact Apple system-tool paths and BLAKE3 digests only under the exact reviewed `SystemVersion.plist` BLAKE3. Bundled `rg` must match its exact canonical path shape, binary BLAKE3, and OS profile before bounded, deadline-limited Codesign identity inspection runs. Codesign-reported identifier/team fields are descriptive metadata only; they do not establish strict signature validity or replace BLAKE3 byte authentication. Unknown OS or executable updates fail closed until reviewed into a new policy/profile.
- Installation is not an eligibility claim. Linux and unknown macOS profiles may run the CLI, but reuse stays disabled until an execution backend/profile is audited; doctor reports either the exact audited Apple profile or an unsupported code.
- V0 rejects admission if any `DYLD_*`, `LD_*`, `Malloc*`, `MALLOC_*`, `{ASAN,LSAN,MSAN,TSAN,UBSAN}_OPTIONS`, `GCONV_PATH`, `LOCPATH`, `NLSPATH`, `PATH_LOCALE`, `TERMCAP`, `TERMINFO`, `TERMINFO_DIRS`, or `TZDIR` variable is present. These names can redirect loading or data lookup to external bytes that the scoped fingerprint does not model.
- Cache keys and stored proofs bind real/effective uid and gid, the supplementary-group vector, supported macOS soft/hard resource limits, and current signal mask/disposition/flag state. A context change partitions the cache.
- On a local hit, Again revalidates the request fingerprint, exact executable/profile, runtime-context digest, every v0 record field, result status/policy/size constraints, and CAS blob bytes. It then spawns the exact executable with fixed cheap probe arguments to confirm current exec authority before replay; it does not rerun the requested argv. A metadata mismatch is quarantined and aborts fail-closed.
- The capability probe and filesystem observations are point-in-time checks, not immutable snapshots. Plan-to-use/concurrent-mutation races remain, and transient global resource availability may change after a successful cheap probe or differ from what the requested work would have needed.
- A cold admitted execution streams stdout and stderr live while capturing bounded copies. Reusable admission requires exit status zero, empty stderr, complete captures no larger than 16 MiB per stream, stable post-execution observations, and an exact shadow execution. Each local blob is capped at 16 MiB. Non-zero, signaled, nonempty-stderr, oversized, incomplete, networked or externally effectful executions are not stored as reusable v0 results, but already-presented cold output is not truncated by the cache capture limit.
- Every cache hit returns complete stdout and stderr. Automatic compact references are disabled because Codex hooks expose neither the effective output ceiling nor a delivery receipt. Production returns before parsing `PreCompact`/`PostCompact`; the unsafe experimental parser treats them as state-free no-ops. The delivery ledger and clearing primitives are dormant future infrastructure, not a current output-reduction feature.
- Once child output has been successfully presented, later fingerprint, shadow, serialization, storage, event, or hit-accounting failures do not replace the child or cached result status. Output-presentation failure itself may still surface as an error.
- Remote records are treated as untrusted. For a manually provisioned team profile, `again team run` recomputes the request/runtime bindings, obtains fresh offline-root-signed repository trust, durably checkpoints its monotonic epoch, applies producer/record revocations and allowlists, verifies the producer signature and ciphertext identity, authenticates/decrypts locally, and rescans plaintext before release. Those controls do not solve bootstrap: an operator must still provision the endpoint, pinned root, keys, policies, and least-privilege credentials consistently, and there is no hosted service or public control plane.

`again setup --codex` manages only an instruction skill, never hooks. Its default personal scope is `$HOME/.agents/skills/again`; `--project` selects `<repo>/.agents/skills/again`. Installation and removal use an ownership record and refuse symlinked paths, unowned existing skills, partial state, or user-modified owned files rather than overwriting them. Production hook code remains no-op experimental plumbing.

## Local state trust boundary

On Unix, the disposable default root is `${TMPDIR}/again-<euid>/workspaces/<BLAKE3(canonical-workspace-path)>`, outside the observed workspace; app-owned directory levels are private mode `0700`, and default state creation never mutates the workspace. `AGAIN_HOME` selects one exact persistent root. It must be absolute and outside the active workspace, its final component cannot be a symlink, and an existing root must already be an effective-user-owned real directory with mode `0700`. Again walks the canonical ancestor chain: each ancestor must be a real directory owned by the effective uid or root, and every group/world-writable ancestor must have sticky protection. Again also rejects static database, WAL/SHM, blob-directory, blob-shard, blob-file, and state-root `.gitignore` symlinks. Fixed files must be regular, owned by the effective user, mode `0600`, and have one hard link; fixed directories must be owned real directories with their required private modes. These checks reject foreign ownership and insecure preexisting state instead of repairing it silently. The source repository's `/.again` ignore applies only at its root and is not a runtime state-location or nested-ignore rule.

This hardens fixed-path setup and ordinary reads; it is not a hostile same-user or root boundary. A same-user or root process can still replace path components between validation and use, and a same-user process can write unauthenticated SQLite rows. The database and filesystem namespace remain trusted local inputs until descriptor-relative/immutable access and metadata authentication exist.

## Threats covered now

Current tests cover shell injection and nested wrapping; experimental exact-hook-envelope rejection; production hook no-op behavior; PATH/basename spoofing; exact reviewed Apple executable identities and unknown-profile refusal; path traversal, runtime namespaces, explicit recursive `.git` aliases, symlink escape/cycles and special files; `rg` ordering/ignore requirements; forbidden ambient-input names plus environment, executable and resource-limit drift; directory membership, absent-path, restored-mtime, inode and ctime invalidation; static state symlinks, ownership, configured-ancestor sticky-mode rules and hard links; corrupt blobs; semantic result-metadata tampering; concurrent identical/divergent result writers and quarantine; experimental malicious hook JSON; non-zero-result admission; fixed two-run equality; and exact full-stream recovery. Success-path macOS E2Es run only when the host matches the exact audited OS and every audited Apple-tool BLAKE3. There is not yet a malicious same-user metadata-authentication boundary, descriptor-relative state/path access, deliberate shadow-divergence fixture, concurrent filesystem-mutation fixture, same-user/root parent-race fixture, comprehensive signal/group-context fixture, transient-global-resource model, or local oversized-output admission test.

The deterministic generated corpus contains 100,000 policy classifications, four scoped-fingerprint differential representatives, and up to six fixed two-run system-command fixtures. It broadens regression coverage for the audited v0 model, but it is not 100,000 executions, fingerprints, cache hits or evidence of general equivalence.

The undeployed team-service prototype adds locally tested tenant/repository isolation, repository-generation fencing, encrypted content-addressed streams, root-signed trust, producer signatures and revocation, quota accounting, bounded lifecycle recovery, conflict quarantine, and strict async Rust transports. The manually provisioned team-alpha CLI is integrated with those transports and verifies/decrypts records locally. The two-request `bundle_v1` transport is manually selectable for controlled experiments but remains unshipped; operator and CI examples use `legacy_v2`. There is still no self-service bootstrap, deployed endpoint, external security review, or production operations evidence. Precise controls and residual risks are in [`docs/REMOTE_THREAT_MODEL.md`](docs/REMOTE_THREAT_MODEL.md). This is not a production security claim.

The following remain roadmap requirements: complete descendant/effect tracing, immutable/COW Linux execution, crash-atomic effect records, local-v0 secret-taint classification, self-service team profile/key/credential provisioning and rotation, pre-authentication edge abuse controls, complete tenant deletion and bounded ambiguous-object operations, production IAM/monitoring/recovery, and independent security review.

## Reporting

This is a pre-alpha repository. Report security issues directly to the repository owner and do not place exploit details in ordinary issues. A public disclosure address and response SLA will be added before a production release.
